# 命令参考

本文档列出 hx 的全部命令、选项、退出码和环境变量。入门用法见 [README](../README.md)。

## 通用约定

```
hx [-C 项目目录] <命令> [选项]
```

| 全局选项 | 说明 |
|---|---|
| `-C`, `--project <目录>` | 指定项目目录，默认为当前目录 |
| `--version` | 显示版本号 |
| `-h`, `--help` | 显示帮助；也可用于任一子命令 |

不带任何命令运行 `hx`，会显示当前项目的保存状态和下一步建议。

### 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 命令已执行，但有需要处理的事项（例如体检发现问题、还原时存在冲突、用户取消） |
| 2 | 出错，命令未完成（例如项目尚未保存过、包格式不兼容、git 版本过旧） |

### 快照的写法

接受"快照"参数的命令，既可以写快照 ID（或它的前几位），也可以写任意 git 版本（提交号、分支名、标签）。

## 日常命令

### hx save

保存当前项目的 Agent 环境。等价于"需要时初始化 → 抓取 → 提交"。

```
hx save [-m 说明] [--push]
```

| 选项 | 说明 |
|---|---|
| `-m`, `--message <说明>` | 本次保存的说明。省略时根据变化自动生成，例如"技能 1 项，会话 2 项" |
| `--push` | 保存后推送到远端（仅当当前分支已设置上游时） |

行为细节：

- 项目尚未初始化时自动初始化，并自动识别这台机器上用于该项目的 Agent。
- 发现这台机器上用另一种受支持的 Agent 做过该项目时，自动将其登记到项目中。
- 只提交 `.harness/` 目录，不触碰其他文件。
- 内容没有变化时不产生新提交。
- 目录不是 git 仓库时仍会写入 `.harness/`，只是没有历史记录。
- 仓库处于合并或变基过程中时，只更新文件，不提交。
- `.harness/` 中存在合并冲突时自动解决：清单和声明取两边的并集，锁文件和交接简报重新生成，本机已安装的 Agent 的目录以本机为准。意图、任务、决策、记忆等人工内容的冲突留给用户。
- 快照引用的项目文件存在未提交的改动时，会给出提醒。

### hx load

把项目中保存的 Agent 环境载入本机，并检查环境。等价于"取得项目 → 预览 → 确认 → 还原 → 体检"。

```
hx load [来源] [-y] [--force] [--dry-run]
```

| 参数与选项 | 说明 |
|---|---|
| `来源` | 可选。git 仓库地址、本地仓库目录，或 `.hxb` 包文件。省略时载入当前项目 |
| `-y`, `--yes` | 不询问，直接载入 |
| `--force` | 覆盖本机已有的不同文件；原文件备份为 `<文件名>.hx-bak` |
| `--dry-run` | 只列出将要放置的文件，不写入 |

行为细节：

- 写入前列出目标文件并要求确认。在非交互环境中必须显式加 `--yes`。
- 只为本机已安装的 Agent 还原配置。
- 本机的 Agent 与保存时不同时，自动进行跨 Agent 转换（技能、MCP 服务器、指令入口）。
- 还原后执行体检，逐条列出缺少的环境变量、命令和插件。

### hx auto

查看或开关自动保存。

```
hx auto [on|off]
```

自动保存由 Claude Code 或 Codex 的 hx 插件会话结束钩子触发，只对已经保存过、且开关为开的项目生效。
Codex 用户需先在 `/hooks` 审阅钩子。Codex 的结束钩子最长 3 秒，因此启动独立后台进程完成本地保存，
结果写入本机 `~/.hx/logs/auto-save-*.log`。强制杀死进程不保证触发钩子，也不会自动推送。

### hx team

查看或开关团队一键接入。

```
hx team [on|off]
```

开启后，hx 在项目配置中声明 hx 插件：Claude Code 使用 `.claude/settings.json`；
Codex 使用 `.codex/config.toml` 的 `[marketplaces.hx]` Git 来源和 `[plugins."hx@hx"] enabled = true`。
Codex 必须先信任项目，安装或刷新由 Codex 处理，不保证弹出安装窗口；钩子仍需用户审阅。
关闭 Codex 接入会把该项目的插件设为禁用，保留市场来源及其他设置。已有不同的 hx 市场不会被覆盖。
被修改的文件此前没有未提交改动时，hx 会将其单独提交。

## 可搬运性与隐私

### hx audit

```
hx audit [--all]
```

扫描 `.harness/`，列出脱敏规则无法判断、需要人工确认的内容：邮箱、IP 地址、内网域名、手机号、其他人的主目录路径、形似密钥的随机字符串。每类默认显示前 10 处，`--all` 显示全部。疑似密钥只显示首尾几个字符。

有发现时退出码为 1。建议在推送或导出前运行。

### hx private

```
hx private [list]
hx private add <真实的词> <代称>
hx private remove <真实的词>
```

登记私有词。之后保存时，包内所有文本中的该词替换为 `[[代称]]`；载入时，本机对照表中有该代称的会换回原词，没有的保持代称。

- 对照表保存在本机的 `~/.hx/terms.json`，不进入项目，对所有项目生效。
- 需要团队成员都能看到原词时，通过其他安全渠道把对照表发给他们。
- 已经提交的快照不会被改写，登记后需要重新保存。

### hx resource

```
hx resource [list]
hx resource add <名字> --path <产物路径> --build <重建命令> [--sources <通配符>]… [--note <说明>]
hx resource remove <名字>
```

登记由源文件生成、不应随项目迁移的数据，例如向量库和检索索引。

| 选项 | 说明 |
|---|---|
| `--path` | 产物在项目中的相对路径 |
| `--build` | 重建命令。hx 只展示，不执行 |
| `--sources` | 源文件的通配符，可重复指定。用于判断产物是否过期 |
| `--note` | 补充说明，例如所用的向量模型 |

体检按修改时间判断状态：产物不存在为"还没有生成"，任一源文件比产物新为"比源文件旧"。产物路径未被 git 忽略时，登记时会提醒。

体检还会提示项目中疑似向量库、但尚未登记的目录和文件。

### hx claim

```
hx claim [list]
hx claim add <说法> [--path <路径> | --env <变量名> | --command <命令名>]
hx claim remove <编号>
```

记录 Agent 的工作所依赖的、项目之外的状态。

| 核对方式 | 载入时的行为 |
|---|---|
| `--path` | 检查文件或目录是否存在。相对路径相对于项目；`~` 开头相对于主目录 |
| `--env` | 检查环境变量是否已设置 |
| `--command` | 检查命令是否已安装 |
| 不指定 | 无法自动核对，提醒接手的人核实 |

核对只做存在性检查，不执行任何命令。声明是快照的一部分，会出现在交接简报中。

## 历史命令

### hx log

```
hx log [--all]
```

列出快照历史：快照 ID、时间、提交号、说明，以及所用的 Agent、模型和对应的代码提交。`--all` 改为列出所有带快照标记的提交，包括代码提交（需要先运行 `hx hook`）。

### hx diff

```
hx diff [快照A] [快照B] [--raw]
```

按类别（指令、设置、技能、MCP、插件、记忆、会话等）报告两个快照之间新增、删除和修改的文件，以及 Agent 版本和模型的变化。

| 用法 | 比较对象 |
|---|---|
| `hx diff` | 最近的快照与当前状态（会先重新抓取） |
| `hx diff A` | 快照 A 与当前 `.harness/` |
| `hx diff A B` | 快照 A 与快照 B |

`--raw` 同时输出文件内容级别的差异。

### hx restore

```
hx restore <快照>
```

把 `.harness/` 恢复为指定快照的内容。不会自动还原到本机，也不会自动提交；之后运行 `hx load` 应用到本机，运行 `hx save` 将这次回退记录为新的快照。

### hx hook

```
hx hook
```

安装 git 的 `prepare-commit-msg` 钩子。之后每个提交的说明末尾都会带上当时的快照 ID（`Hx-Snapshot`），由此可以查到任意一次代码提交是在哪个 Agent 环境下产生的。

## 分发命令

### hx export

```
hx export [-o 输出路径] [--include-transcripts]
```

导出为单个自包含的 `.hxb` 文件，内含 `.harness/` 和锁文件引用的项目文件。默认文件名为 `<项目名>-<快照ID>.hxb`。

`--include-transcripts` 额外包含脱敏后的原始对话记录。原始对话内容多、敏感信息风险高，分享前请人工检查。

### hx import

```
hx import <包文件> [--force] [--restore-transcripts]
```

把 `.hxb` 解到项目目录。已有的不同文件默认不覆盖。`--restore-transcripts` 把包中的原始对话放回 Agent 的数据目录，属于实验性功能。

多数情况下直接使用 `hx load <包文件>` 即可，它包含了导入、还原和体检。

## 分步命令

`save` 和 `load` 由下列步骤组成。需要精细控制时可以单独使用。

| 命令 | 作用 |
|---|---|
| `hx init [--agent 名称]` | 创建 `.harness/`。`--agent` 可指定一个或多个 Agent，用逗号分隔，例如 `claude-code,codex` |
| `hx capture` | 抓取并更新 `.harness/`，不提交 |
| `hx snapshot -m 说明 [--no-capture]` | 抓取并提交。`--no-capture` 直接提交 `.harness/` 的当前内容 |
| `hx doctor` | 体检：文件是否与锁一致、环境变量、Agent、git 版本、MCP 命令、插件、保存来源、可重建资源、外部状态声明、待还原项 |
| `hx materialize [--force] [--dry-run] [-v]` | 还原到本机，不询问。`-v` 同时列出已经一致的文件 |

## 环境变量

| 变量 | 作用 |
|---|---|
| `HX_HOME` | 把指定目录当作用户主目录。用于测试或模拟另一台机器。设置后，hx 忽略 `CLAUDE_CONFIG_DIR` 和 `CODEX_HOME`，也不探测本机 Agent 的版本 |
| `HX_PLUGIN_REPO` | `hx team on` 声明的插件仓库，默认 `Source123123/hx`。使用自己的分支时设置 |
| `CLAUDE_CONFIG_DIR` | Claude Code 的配置目录，默认 `~/.claude` |
| `CODEX_HOME` | Codex 的配置目录，默认 `~/.codex` |
| `CLAUDE_PROJECT_DIR` | 由 Claude Code 在钩子中提供，hx 的自动保存据此定位项目 |

## Claude Code 插件提供的入口

| 入口 | 作用 |
|---|---|
| `/hx:save` | 由 Agent 执行 `hx save` 并说明结果；首次保存时询问是否开启团队一键接入 |
| `/hx:load` | 由 Agent 预览、征求同意、执行 `hx load`，说明待处理事项，并概括交接简报 |
| 会话结束钩子 | 对已保存过且开启自动保存的项目执行保存 |
| 会话开始钩子 | 提示 Agent 阅读交接简报；有配置尚未载入时提示用户。不写入任何文件 |

## Codex 插件入口与钩子

安装见 README。插件中的 `$hx:save` / `$hx:load` 对应 Claude Code 的 `/hx:save` / `/hx:load`。
技能都通过插件自带启动器运行，不需要 pip。载入先预览；明确授权后才使用 `--yes`，不同文件默认不覆盖。
项目技能的当前位置是 `.agents/skills`；保留 `.codex/skills` 的兼容内容。旧的 `~/.codex/prompts` 仍保存，但新入口不用它。
个人 `AGENTS.md` 和优先级更高的 `AGENTS.override.md` 均可保存与还原。

`hx auto-load` / `hx auto-save [--background]` 是钩子入口：

- 优先从标准输入的 JSON 读取 `cwd`，兼容 Codex 和 Claude Code；缺省使用 `CLAUDE_PROJECT_DIR`，再使用 `-C` 或当前目录。
- 从子目录启动时向上找当前 git 仓库里的 `.harness`，不跨越其他 git 项目。
- `auto-load` 只报告，不写文件；`auto-save` 只对已管理且开启的项目本地提交 `.harness/`。
- Codex Windows 钩子使用 PowerShell 调用 `bin/hx.cmd`；macOS/Linux 使用 `bin/hx`。
- 普通 `codex exec` 在本轮版本中没有发出 `SessionStart`，交互式客户端的 `startup` 事件才会触发开始提示。

项目级 MCP 的配置需要 Codex 信任项目才能生效。hx 保存用户层和项目层的有效配置，项目来源仍还原到项目。
Codex 插件清单仅用于检查缺少、禁用或版本差异，不自动安装；生成记忆是用户级状态，不按项目复制。

可重复运行的真实迁移检查：`python -X utf8 tests/manual_codex_e2e.py`。
它需要已登录的 Codex 并消耗模型额度，使用临时目录验证保存、clone、载入、MCP 和技能，不改真实主目录配置。
