# 设计说明

本文档说明 hx 的设计目标、整体结构和主要取舍。文件格式的精确定义见 [FORMAT.md](FORMAT.md)，命令行为见 [COMMANDS.md](COMMANDS.md)。

## 1. 目标与非目标

### 1.1 目标

1. **可迁移**：在一台机器上抓取项目的 Agent 环境，在另一台机器上还原出相近的环境。
2. **可追溯**：Agent 环境的每次变化都形成一次提交，构成可以查看、比较、回退的历史。
3. **可关联**：记录"代码提交"与"当时的 Agent 环境"之间的对应关系。
4. **与 Agent 无关**：中间格式不绑定具体的 Agent，通过 adapter 接入。
5. **低使用成本**：日常只有"保存"和"载入"两个动作，能自动完成的不要求用户操作。

### 1.2 非目标

- **不保证行为可重放。** 模型输出有随机性，旧模型会下线。hx 保证的是配置和上下文一致。
- **不打包密钥。** 包里只记录需要哪些环境变量。
- **不重造环境工具。** 系统依赖交给 Dev Container、Nix、Docker，hx 只引用它们。
- **不重造版本控制。** hx 的历史就是 git 历史。

## 2. 分层模型

| 层 | 内容 | hx 的处理 |
|---|---|---|
| L0 代码 | 源码 | 交给 git，仅记录提交号 |
| L1 运行环境 | devcontainer、Dockerfile、flake.nix、版本文件 | 引用并记录哈希 |
| L2 Agent 配置 | 指令、技能、子 Agent、命令、钩子、权限、插件、MCP | 项目内的引用，项目外的复制进包 |
| L3 上下文 | 记忆、会话摘要、意图、决策、任务 | 提炼后进包；原始对话可选归档 |
| L4 行为 | 重新运行的结果 | 不处理，只提供追溯 |

## 3. 核心规则

### 3.1 引用与复制

Agent 的配置分散在两处，hx 区别对待：

- **项目内**（如 `CLAUDE.md`、`.claude/`、`.mcp.json`）：已经随仓库版本化，hx 只在锁文件中记录路径和哈希。
- **项目外**（主目录下的个人指令、技能、记忆、会话）：换机器即丢失，hx 复制进 `.harness/`，复制时脱敏。

这样既避免同一份文件在仓库里保存两遍，又保证迁移出去的内容完整。

### 3.2 提炼优先于归档

原始对话记录体积大、噪声多、敏感信息风险高。hx 默认只保存每个会话的摘要：用户的要求、改动的文件、工具使用次数、最后的答复。原始对话只在显式要求导出时才进入包文件。

人工维护的 `intent.md`、`tasks.md`、`decisions/` 承载会话摘要表达不了的内容：为什么这样设计、放弃了什么方案、还剩什么没做。hx 不会覆盖它们。

### 3.3 内容寻址

快照 ID 由 Agent 信息和所有条目的内容哈希算出。内容相同则 ID 相同，与机器、操作系统、时间无关。交接简报不参与计算，因此提炼器输出不稳定不会制造多余的快照。

### 3.4 静态快照与动态系统

快照是静态的，而 Agent 的环境是动态的：它依赖外部世界，并且随时间变化。hx 不试图冻结动态的部分，而是把内容按"能否带走"分成四类，分别处理。

| 类别 | 例子 | 处理 | 理由 |
|---|---|---|---|
| 可携带 | 指令、技能、决策 | 复制并脱敏 | 内容本身就是知识，与机器无关 |
| 与机器绑定 | 绝对路径、用户名、私有名称 | 保存为占位符，载入时换成本机的值 | 原值在别处既无效又泄露信息；占位符保留了结构 |
| 可派生 | 向量库、索引、缓存 | 只保存重建方法和源文件指纹 | 体积大、是二进制、无法比较差异；而且向量可以被反推出原文，并不构成脱敏 |
| 外部状态 | 数据库内容、远端服务、本机工具 | 保存为声明，载入时重新核对 | 无法打包；不记录则 Agent 会把旧记忆当成当前事实 |

对应的三条设计约束：

- **记忆有来源。** 锁文件记录最近一次保存发生在哪台机器（匿名标识）和什么系统。在另一台机器上载入时给出提示；交接简报开头注明其中的内容是历史记录。
- **核对不等于执行。** 声明的核对只做存在性检查；资源的重建命令只展示，不运行。包里带来的内容永远不会被 hx 当作命令执行。
- **不自动发现依赖。** hx 无法知道 Agent 依赖了哪些外部状态，这需要人或 Agent 写下来。插件的保存入口会提示 Agent 在保存前记录。

模型本身的变化（厂商更新模型）同样属于外部状态。hx 记录保存时的模型和 Agent 版本，并在比较快照时显示变化，但不试图消除它。

## 4. 结构

```
┌─────────────────────────────────────────────────────────────┐
│ cli.py                命令行、输出、交互确认                  │
├─────────────────────────────────────────────────────────────┤
│ core.py               流程编排：抓取、快照、比较、还原、体检、 │
│                       打包、团队接入                         │
├──────────────┬──────────────┬──────────────┬────────────────┤
│ adapters/    │ redact.py    │ handoff.py   │ gitutil.py     │
│ 各 Agent 的  │ 脱敏规则      │ 交接简报      │ git 封装       │
│ 文件位置与格式│ portable.py  │ 提炼器        │                │
│              │ 占位符、审查  │ extras.py    │                │
│              │              │ 资源、声明    │                │
└──────────────┴──────────────┴──────────────┴────────────────┘
```

- **核心**只处理通用流程，不了解任何 Agent 的文件位置和格式。
- **adapter** 回答三个问题：这个 Agent 的东西在哪、是什么格式、还原时放回哪里。
- **扩展点**（adapter、脱敏规则、提炼器）通过 Python 的 entry point 注册，见 [EXTENDING.md](EXTENDING.md)。

## 5. 版本模型

- 一次保存等于"抓取 + 一次只包含 `.harness/` 的 git 提交"。
- 提交说明带有标记：快照 ID、Agent 及版本、模型、对应的代码提交。
- 分支和合并直接使用 git。为了让合并可行，`.harness/` 的内容按冲突时的处理方式分为三种：
  - **生成的文件**（锁文件、交接简报）：冲突时丢弃，重新生成。
  - **结构化的集合**（清单中的列表、外部状态声明、会话摘要）：每项独立，冲突时取并集。会话摘要一个会话一个文件，不同会话之间不会冲突。
  - **人写的内容**（意图、任务、决策、记忆）：冲突时交给人判断。

  hx 不合并对话记录。它保存的是互相独立的摘要，而不是需要保持先后顺序的对话流。
- 可选的 git 钩子为每个代码提交加上当时的快照 ID，从而可以由任意代码提交查到产生它的 Agent 环境。
- 比较两个快照时，按类别报告新增、删除、修改的文件，以及 Agent 版本和模型的变化。

## 6. 还原

还原遵循保守原则：

| 目标位置的状态 | 行为 |
|---|---|
| 不存在 | 写入 |
| 内容相同（忽略换行差异） | 跳过 |
| 内容不同 | 保留原文件并报告；显式强制时先备份再覆盖 |

MCP 服务器按名称合并：只添加不存在的，同名但内容不同的保留原样并报告。

锁文件中的还原路径必须落在 Agent 配置目录或项目目录之内，否则拒绝执行。

## 7. 一键使用

日常操作收敛为两个动作：

- **保存**：未初始化则初始化，抓取，可提交则提交；提交说明自动生成。
- **载入**：取得项目，预览，确认，还原，体检，并逐条说明待处理事项。

仓库本身同时是一个 Claude Code 插件，自带不依赖 pip 的启动器：

- 两个命令入口，由 Agent 代为执行并用自然语言说明结果。
- 会话结束钩子执行自动保存，仅对已保存过且开启该功能的项目生效。
- 会话开始钩子**只报告，不写入**：提示 Agent 阅读交接简报，提示用户有配置待载入。

**为什么不自动载入。** 载入会把项目带来的设置写入用户主目录，其中可以包含钩子命令。如果打开仓库就自动写入，恶意仓库可以借此在用户机器上执行代码。因此载入必须经过一次明确的确认。

## 8. 多 Agent 与跨 Agent

### 8.1 一个项目，多个 Agent

- 清单中的 `agents` 是列表。保存时如果发现本机用另一种受支持的 Agent 做过该项目，自动加入。
- 抓取时逐个 adapter 处理。**本机未安装的 Agent 直接跳过，它在包里的内容和锁文件条目原样沿用。** 使用 Codex 的成员保存时，不会抹掉使用 Claude Code 的成员留下的配置。
- 锁文件的每个条目标明所属的 Agent。
- 会话摘要全团队累积，只保留最近的若干个；更早的保留在 git 历史中。

### 8.2 跨 Agent 交换

还原时只处理本机已安装的 Agent。本机已安装、但包里没有其内容的 Agent，进入"接收"流程：

```
已保存内容的 adapter ──export_neutral()──▶ 中立内容 ──adopt()──▶ 本机的 adapter
                                          技能文件
                                          MCP 规范
                                          指令文件路径
```

N 种 Agent 只需要 N 个 adapter，不需要两两编写转换。

| 内容 | 处理方式 |
|---|---|
| 技能 | 两边格式相同，直接复制 |
| MCP 服务器 | 经中立写法转换，密钥保持由环境变量提供 |
| 指令文件 | 不复制内容，只生成指向原文件的入口，避免两份内容不一致 |
| 权限、钩子、插件 | 各 Agent 不通用，不转换 |

### 8.3 已知取舍

同一种 Agent 的个人配置以最后保存的人为准。两名成员都使用 Claude Code 时，后保存者的个人技能会替换包里的那一份。由于后保存者载入时已经取得前一人的技能，结果通常是并集；但如果未载入就保存，前一人的内容会从当前快照中消失，只留在 git 历史里。

## 9. 跨操作系统

| 问题 | 处理 |
|---|---|
| 换行符 | 文本内容统一为 LF 后再计算哈希；包内文本一律 LF；`.harness/.gitattributes` 禁止 git 转换；比较文件时忽略换行差异 |
| 路径 | 锁文件和摘要中只有以 `/` 分隔的相对路径；判断路径是否在项目内时统一分隔符，Windows 上不区分大小写 |
| 编码 | 所有文件为 UTF-8；输出被其他程序接收时强制 UTF-8；无法输出的字符以 `?` 代替而不是报错 |
| 启动器 | `bin/hx` 用于 macOS、Linux 和 Git Bash，`bin/hx.cmd` 用于 Windows 命令提示符；两者都会确认找到的 Python 真实可用 |

## 10. 兼容性

- **格式版本**：清单和锁文件各自带有版本号。新版读取旧格式并在下次保存时升级；旧版遇到新格式时拒绝读取并提示升级，而不是按错误的理解去还原。
- **Python**：只使用标准库。Python 3.11 之前没有内置的 TOML 解析器，hx 为此带有一个仅覆盖 Codex 配置所需语法的简化解析器。
- **git**：读取提交标记需要 git 2.22；版本不足时给出明确提示。
- **Agent 版本**：adapter 对 Agent 的文件做防御性读取，缺失或无法识别的部分跳过而不是报错。本机 Agent 版本与快照不同时，体检给出提醒。
